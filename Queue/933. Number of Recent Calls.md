
```js
class RecentCounter {
  constructor() {
    // Initialize our empty queue
    this.queue = [];
  }

  ping(t) {
    // 1. A new ping arrives! Get in the back of the line.
    this.queue.push(t);

    // 2. Look at the front of the line. 
    // Is the oldest ping outside of our 3000ms window?
    // t - 3000 is the cutoff time. Anything smaller is too old.
    while (this.queue.length > 0 && this.queue[0] < t - 3000) {
      // Kick the oldest ping out of the front of the line!
      this.queue.shift(); 
    }

    // 3. Everyone left in the queue is within the last 3000ms.
    return this.queue.length;
  }
}
```

```js
var RecentCounter = function() {
    // This acts exactly like the constructor(). 
    // We initialize our empty queue here.
    this.queue = [];
};

/** * @param {number} t
 * @return {number}
 */
RecentCounter.prototype.ping = function(t) {
    // 1. Add the new ping to the back of the line
    this.queue.push(t);

    // 2. Kick out any pings from the front that are older than 3000ms
    while (this.queue.length > 0 && this.queue[0] < t - 3000) {
        this.queue.shift();
    }

    // 3. Return the number of valid pings left in the queue
    return this.queue.length;
};
```

### The Translation Guide

If you ever see this weird `prototype` stuff again, here is the secret decoder ring:

- `var ClassName = function() { ... }` is literally just the `constructor()`. It's where you set up your initial variables.
    
- `ClassName.prototype.methodName = function() { ... }` is just adding a method to that class.
    

Under the hood, JavaScript classes are actually built using this exact prototype system anyway. The `class` keyword we use today is just "syntactic sugar"—a nicer-looking wrapper around this older syntax!
