
```js
class RecentCounter {
  constructor() {
    // Initialize our empty queue
    this.queue = [];
  }

  ping(t) {
    // 1. A new ping arrives! Get in the back of the line.
    this.queue.push(t);

    // 2. Look at the front of the line. 
    // Is the oldest ping outside of our 3000ms window?
    // t - 3000 is the cutoff time. Anything smaller is too old.
    while (this.queue.length > 0 && this.queue[0] < t - 3000) {
      // Kick the oldest ping out of the front of the line!
      this.queue.shift(); 
    }

    // 3. Everyone left in the queue is within the last 3000ms.
    return this.queue.length;
  }
}

// How it looks in action:
// const counter = new RecentCounter();
// counter.ping(1);    // queue: [1], returns 1
// counter.ping(100);  // queue: [1, 100], returns 2
// counter.ping(3001); // queue: [1, 100, 3001], returns 3
// counter.ping(3002); // queue: [100, 3001, 3002], (1 was kicked out!), returns 3
```


### The Translation Guide

Older LeetCode editorials sometimes show this exact solution written in the legacy "prototype" style because of their skeleton code. The `class` above is the modern way; here is the secret decoder ring for how that older style maps onto it:

- `var ClassName = function() { ... }` is literally just the `constructor()`. It's where you set up your initial variables (here, `this.queue = []`).
    
- A method written as `ClassName.prototype.methodName = function() { ... }` is just adding a method to that class (here, `ping(t)`).
    

Under the hood, JavaScript classes are actually built using this exact prototype system anyway. The `class` keyword we use today is just "syntactic sugar"—a nicer-looking wrapper around this older syntax!
